ECOMIQ
UI & Frontend Product Brief
Product Design & Frontend Engineering Reference
1. Product Overview
EcomIQ is a modern, data-heavy e-commerce operations and intelligence platform designed for D2C brands and e-commerce businesses.
The platform brings operational, logistics, financial and marketing data into a single workspace and turns that data into actionable intelligence.
Core product idea: EcomIQ = Operations + Data + Intelligence.
The UI should allow a business user to move through the workflow: What happened → Why did it happen → What should I do?
2. Target Users
Business Owner / Founder — business health, revenue, orders, shipping, COD, NDR, marketing and AI insights.
Operations Manager — orders, shipments, NDR, courier performance, delivery performance, weight issues and exceptions.
Finance Team — COD, shipping charges, wallet, transactions, reconciliation, invoices and credit notes.
Customer Support Team — orders, shipment tracking, NDR, customer history and delivery issues.
Marketing Team — Meta Ads, Google Ads, Amazon Ads, campaign performance, ROAS, CAC and revenue attribution.
Admin — workspaces, users, stores, integrations, courier accounts, billing and permissions.

5. Application Shell
Desktop is the primary experience. The shell should provide a consistent navigation and workspace context across the product.
Left navigation: Dashboard, Orders, Shipments, NDR, Weight, Couriers, Warehouses, Customers, Finance, Marketing, Analytics, AI Insights, AI Chat, Settings.
Header left: EcomIQ logo and workspace selector.
Header center: global search.
Header right: AI Assistant, Notifications, Help and Profile.
The shell must support persistent context, breadcrumbs where useful, and fast navigation.
6. Dashboard
The dashboard is the executive command center. It should answer business, operational, financial, marketing and intelligence questions at a glance.

Include date ranges such as Today, Yesterday, 7 Days, 30 Days and Custom, with comparison to the previous period.
7. Orders Module
Orders should be a high-density operational table.
Columns: Order ID, Date, Customer, Items, Amount, Payment, Channel, Warehouse, Shipment, Status, Actions.
Search, advanced filters, date filter, store filter, payment filter, order status, bulk actions, export and column customization.
Order detail should include Order Information, Customer Information, Items, Payment, Shipping, Warehouse, Shipment Timeline, NDR, Financial Information and Activity Log.
8. Shipments Module
Shipment management is a core operational module.
Table: AWB, Order ID, Courier, Origin, Destination, Status, EDD, Actual Delivery, Weight, Shipping Cost, NDR and RTO.
Shipment detail should include shipment timeline, tracking events, courier, package information, addresses, charges, weight, NDR history and RTO information.
Timeline example: Order Created → AWB Assigned → Picked Up → In Transit → Out for Delivery → Delivered.
9. NDR Module
NDR should be designed around actionability, not just reporting.
Show NDR shipments, action required, resolved cases and recovery rate.
Table: AWB, Order, Customer, Courier, NDR Reason, Attempt, Age, Status and Action.
Actions can include Call Customer, WhatsApp Customer, Reschedule, Change Address, Reattempt and RTO.
10. Weight Management
Show Declared Weight, Courier Weight, Difference, Additional Charge and Dispute Status.
Provide a clear detail view and an obvious Raise Dispute action.
The UI should make financial impact visible without requiring users to calculate differences manually.

17. AI Insights
AI Insights is a key EcomIQ differentiator. The system should automatically identify meaningful patterns and explain them.
Recommended information hierarchy:
Observation — What changed?
Explanation — Why did it change?
Action — What should the operator investigate or do next?
Example: 'NDR increased 18% this week' → identify the main contributors → show affected shipments → provide an actionable next step.
18. AI Chat
AI Chat should behave like a business intelligence copilot.
Natural-language questions about revenue, orders, couriers, RTO, NDR, shipments, customers and marketing.
Responses can include text, tables, charts, KPI cards, drill-down links and follow-up questions.
Example questions: 'Which courier has the highest RTO rate?', 'Why did delivery performance drop this week?', 'Show orders above ₹5,000 currently in NDR.'

24. UX Principles
Information density without visual clutter.
Actions should be contextual and close to the data they affect.
Drill-down should be available throughout the product.
Preserve user context when navigating between list and detail screens.
Make data explainable — charts should help users understand what changed and why.
Avoid forcing users through multiple screens for common operational actions.
25. Responsive Design
Desktop is the primary application experience, followed by laptop, tablet and mobile.
Mobile should not simply shrink desktop screens. Data-heavy tables should transform into appropriate list/card views where necessary.

29. UX North Star
EcomIQ should be designed around the loop:
DATA  →  INSIGHT  →  DECISION  →  ACTION  →  RESULT
The product should not merely report what happened. It should help the operator understand what happened and take the next action.
30. Design Principle for the Engineer
Do not design EcomIQ as a collection of dashboards. Design it as an operating system for an e-commerce business.
